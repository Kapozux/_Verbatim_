# Verbatim 界面设计规范

这份文档写的是 Verbatim（getAudio）界面「为什么长这样、新东西该放哪」。参照对象是 Google 的
NotebookLM / Gemini Notebook：学它的取舍和交互逻辑，不抄它的样子。改界面前先读这份；
加了新功能，把它补进第 3 节的位置表。

---

## 1. 七条原则

1. **一个区域只做一件主要的事。** 中间栏是对话，左栏是来源，右栏是工作台。次要操作
   （导出、清空、改名、删除、设置）一律收进 ⋯ 菜单或设置弹层，不摆在主界面上抢注意力。
2. **默认状态不占地方，非默认状态必须看得见。** 正常回答时界面上没有任何「模式」控件；
   切到「用他的口吻回答」后，输入框里出现一个「XX 的口吻 ×」标签，一直挂着，点 × 就回去。
   判断标准：用户在这个状态下会不会忘了自己开过它？会，就要有常驻提示。
3. **「做」和「看」分开。** 工作台上面的格子都是「做一份新的」：点了先在页面中间弹设置框，
   确认后结果进下面的列表。只有点列表里的结果，工作台栏才变宽、对话往左收。格子点了
   绝不能直接展开内容。
4. **容器跟着意图走**（见第 4 节）。设置用页面中间的弹框，看结果在工作台栏里展开，看原文
   在来源栏里打开，次要操作用锚定在按钮上的弹层菜单。同一种意图永远用同一种容器。
5. **花钱前说清楚。** 要调模型、会产生费用的按钮，把估价写在按钮上（「生成（约 $0.02）」）；
   没有估价的不要让用户猜。后台在跑的东西，列表那一条转圈，好了自己变成能点的。
6. **先给结论，细节往后放。** 出处是数字小圆点，悬停看「谁 · EP3 · 12:30 + 原话」，点开才跳转；
   统计数字、运行详情收在 ⋯ 里；空状态用一句话说清楚「这里会放什么」。
7. **文案直白。** 说这是什么、点了会怎样。不用比喻和修辞，不用表情符号当图标，英文文案
   不要习惯性用破折号。中英文都要有（`static/i18n.js`），不硬编码。

## 2. 页面结构

```
笔记本列表（首页）
  ├─ 卡片网格：表情/头像 + 名字 + 日期 · 来源数 + ⋮（改名 / 换表情 / 加入合集 / 置顶 / 隐藏 / 删除）
  └─ 合集筛选（合集 = 几个笔记本放在一起，不是一种笔记本）
笔记本页（三栏，一屏高，各栏自己滚）
  ├─ 左：来源      加来源、找来源、勾选范围、读原文
  ├─ 中：对话      问答（永远在这里）
  └─ 右：工作台    上：做新的（格子）  下：做好的（列表，点开在本栏展开）
```

- 笔记本页左上角只有产品图标（点了回列表），没有「返回」和 ☰；顶栏右边是「自动同步」和 ⋯
  （身份、状态、统计、运行详情都在 ⋯ 里）。
- 一个笔记本可以有好几个博主。同一个博主放进几个笔记本时共用一份数据（转写、证据卡、画像、
  镜头只算一次）。画像、镜头、立场、预测、原话按人看，不吃文档；报告、闪卡、自测题、
  对照检查跟着左栏勾选的来源走。

## 3. 功能放在哪（位置表）

| 功能 | 位置 | 怎么触发 | 容器 |
|---|---|---|---|
| 加来源（文件 / 链接 / 频道 / 资料库） | 左栏顶「＋ 添加来源」 | 按钮 | 页面中间弹框 |
| 找来源（网页 / YouTube / B 站） | 左栏搜索框 | 回车 | 结果摆在左栏里，勾了再加 |
| 读原文（文档 / 转写） | 左栏来源标题、回答里的出处 | 点击 | 在左栏里打开，左栏加宽 |
| 提问范围 | 左栏勾选框 | 勾选 | 输入框右侧显示「N 个来源」 |
| 某个博主的全部录音 | 左栏博主那一组的 ⋯ | 菜单项 | 工作台栏展开，面包屑「来源 › 全部录音」 |
| 引用的博主：单独页面 / 移出笔记本 | 左栏博主那一组的 ⋯ | 菜单项 | 跳转 / 确认框 |
| 说话人（声纹认人：试听、改名、合并、拆开） | 左栏来源清单最后一行「说话人」（有录音、装了声纹模型才出现） | 点击 | 工作台栏展开，面包屑「来源 › 说话人」 |
| 代码库（本机 git 仓库，读码 agent Daemon 读出证据卡） | 「＋ 添加来源」弹框里的「代码库」，填文件夹路径 | 按钮 | 加完直接弹中间弹框「读代码库」：问题可空（= 导览）、估价写在按钮上；在读时来源那一行转圈 |
| 带着问题再读一次代码库 / 移出笔记本 | 来源那一行的 ⋯ | 菜单项 | 中间弹框 / 确认框 |
| 看代码库的卡、出处里的代码 | 左栏代码库标题、回答里的出处 | 点击 | 来源栏阅读器：卡片按文件分组；出处点开是文件本身，那几行高亮 |
| 转写里每句是谁说的、▶ 听这一句 | 来源栏阅读器（转写） | 自动标在每句前；▶ 点击 | 就地 |
| 收起来源栏 | 左栏栏头图标 | 点击 | 收成竖栏：展开键、＋、每个来源一个图标 |
| 问答 | 中间栏 | 输入框 | 对话流 |
| 回答方式（讲他们说过什么 / 用他的口吻） | 中间栏栏头的设置图标 | 点击 | 锚定弹层；非默认时输入框里挂标签 |
| 导出对话 / 清空对话 | 中间栏栏头 ⋯ | 菜单项 | 锚定弹层；清空要确认 |
| 一条回答：存进工作台 / 复制 / 导出 | 回答下面一行 | 按钮 | 就地 |
| 人物画像、五个镜头 | 工作台格子「人物画像」 | 点击 | 中间弹框选哪一篇、看谁；做好的进列表 |
| 立场 / 预测对账 / 原话 | 工作台格子 | 点击 | 中间弹框：看谁、状态、估价；「生成」后进列表 |
| 报告 / 闪卡 / 自测题 / 对照检查 | 工作台格子 | 点击 | 中间弹框选格式、范围、重点；后台生成后进列表 |
| 画面证据卡（测试版：读幻灯片 / 图表 / 公式 / 代码上的字） | 工作台格子「画面证据卡」 | 点击 | 中间弹框：全部 / 勾选哪几期、估价；后台一期一期做，列表那一行写「第 i / n 期」；点开在工作台栏里按期分组看卡，时间点点了在来源栏打开转写那一秒 |
| 音频播客（两人对谈 + 本人原声） | 工作台格子「音频播客」 | 点击 | 中间弹框：形式（深入对谈 / 简报 / 辩论，辩论填双方）、长度、重点，估价在按钮上；后台写脚本再录音，列表那一行写「正在录第 i / n 段」；点开在工作台栏里：上面播放器（吸顶），下面逐句文字稿，放到哪句高亮哪句，点句子跳过去，出处圆点照旧去来源栏 |
| 幻灯片（导出可编辑的 .pptx） | 工作台格子「幻灯片」 | 点击 | 中间弹框：样式（详细版 / 演讲版）、页数、侧重，估价在按钮上；后台生成后进列表；点开在工作台栏里：顶上「下载 .pptx」，下面一页页 16:9 预览（版式跟文件一样），每页下面一行写版式和出处圆点，「改这一页」就地展开一行输入框 |
| 对比（同一问题，几个博主各怎么说） | 工作台格子（笔记本里 ≥2 人有卡才出现） | 点击 | 中间弹框选人、写问题；后台生成后进列表 |
| 打开任何一份结果 | 工作台下面的列表 | 点击 | 工作台栏展开，面包屑「工作台 › 类别」 |
| 重新生成镜头 / 删除结果 | 列表那一行右侧 | 图标按钮 | 确认框 |
| 收起工作台 | 右栏栏头图标 | 点击 | 收成 56px 竖栏 |
| 笔记本改名 | 顶栏笔记本名 | 点击就地编辑 | 就地 |
| 换表情 | 对话开头的大表情 | 点击 | 表情弹层 |
| 自动同步 | 顶栏右侧 | 按钮 | 锚定弹层 |

**新功能先问三个问题，再查这张表：**
1. 它是「做一份新的」还是「看已有的」？做新的 → 工作台格子 + 中间弹框；看已有的 → 列表里的一条。
2. 它属于来源、对话还是产出？属于来源 → 左栏；改变对话行为 → 中间栏栏头的设置；产出 → 工作台。
3. 用户一周用几次？每天用的可以有自己的按钮；偶尔用的进 ⋯；只配置一次的进设置。

## 4. 交互模式

| 模式 | 什么时候用 | 实现 | 规则 |
|---|---|---|---|
| 中间弹框 | 做新的前要选东西：格式、看谁、范围、花多少钱 | `.settings-overlay` + `.cx-modal`（`rd-pick` / `st-overlay` / `vp-pick`） | 标题 = 格子名；一句话说明；底部左边状态，右边主按钮；Esc 关 |
| 工作台栏展开 | 看一份结果 | `#nb-viewer` 在 `aside.nb-studio` 里；`#chain-explore.nbv-on`（表格类加 `nbv-wide`） | 面包屑「工作台 › 类别」+ 右上角收起键；标题写这份是什么，格子类不重复写大标题 |
| 来源栏阅读器 | 看原文、核对出处 | `readerOpen()`，`.nb-src.reading` 加宽左栏 | 收起状态下点出处会自动展开左栏 |
| 锚定弹层菜单 | 次要操作、设置 | `<details>` + 绝对定位面板（`.cx-hd-pop`、`.sr-menu`、`.exp-menu`） | 点外面关；窄屏挂在整条栏头上，左右留边 |
| 常驻标签（chip） | 非默认状态 | 例：`.cx-mode-chip` | 写清是什么状态，带 × 一键撤销 |
| 人名标签 | 多人笔记本里选看谁 | `.pp-chip`（头像 + 名字，选中反色） | 放在弹框里，不放在结果顶上（一份结果只属于一个人） |
| 列表行 | 做好的东西 | `.st-item` | 图标 + 标题（「立场 · Y Combinator」）+ 时间 / 状态；在跑的转圈且不能点 |
| 提示条（toast） | 后台开始了 / 做好了 | `showToast()` | 一句话，说结果会出现在哪 |
| 确认框 | 删除、清空、重新生成 | `confirm()` | 说清楚删的是什么、什么不受影响 |
| 空状态 | 列表 / 栏是空的 | `.st-empty`、`.sr-empty`、`.nb-empty-in` | 线条图标 + 一句「这里会放什么」+ 能做的第一步 |

## 5. 视觉规范

- **颜色只用 token**（`static/style.css` 顶部 `:root`）：`--paper --card --ink --ink-soft --muted --faint
  --line --line-2 --coral(-deep/-soft/-line/-strong) --ok --run --bad --code-bg --on-ink --tile-bg --pane-line`。
  深底上的字用 `--on-ink`，不写 `#fff`。新颜色先加 token，暗色两处都要写：
  `:root[data-theme=dark]` 和 `@media (prefers-color-scheme: dark) :root:not([data-theme=light])`。
- **珊瑚色是强调色，不是装饰色。** 主按钮、选中、在跑的状态用它；不放大面积底色。
- **字号**：正文 15–17px，对话回答 17px，次要文字 13–14.5px，标签不小于 12px；标题无衬线、
  常规字重（500），中文不用宋体。
- **图标**：线条 SVG，`viewBox 0 0 24 24`，`stroke-width 1.7`，圆角端点；不用表情符号做 UI 图标
  （表情只用于用户自己给笔记本选的封面）。
- **圆角**：大栏 24px，弹框 / 卡片 16–18px，按钮药丸 999px，小格子 12–14px。
- **按钮**：主按钮珊瑚底白字，一个区域只有一个；次要按钮无框，悬停出 `--code-bg` 底；
  图标按钮 34–40px 圆形。
- **动效**：只用位移和背景色过渡，不动 opacity（后台标签页动画暂停会停在透明）。

## 6. 布局

- 只有一个 `--gutter: clamp(16px, 2vw, 32px)` 和一个 `--shell-w`，左右边缘全站对齐。
- 宽屏（≥1080）笔记本页三栏一屏高（JS 量 `--nb-top`），比例 `1fr : 2fr : 1fr`；工作台展开时
  `0.8fr : 1.25fr : 1.9fr`，表格类 `0.8fr : 1fr : 2.2fr`。栏可收成 56px 竖栏。
- 窄屏（<1080）三栏变成顶上「来源 / 对话 / 工作台」切换，一次一栏；打开结果自动切到工作台。
- ≤700 只改间距，并把锚定弹层挂到整条栏头上。
- **每次改完都要截三个宽度：1700 / 1000 / 400**，浅色和深色各看一遍：左边缘对齐、首屏填满、
  没有横向滚动（`document.documentElement.scrollWidth === innerWidth`）、弹层不出屏。

## 7. 决策记录

| 日期 | 决定 | 为什么 |
|---|---|---|
| 10-01 | 「问关于他的事 / 模拟他回答」从输入框上方挪进对话栏头的设置 | 绝大多数提问用默认方式，常驻切换占地方又让人以为每次都要选；Google 把这类「配置对话」收在设置里。模拟时用输入框里的标签提示，不会忘了开着 |
| 10-01 | 工作台格子 = 做新的，列表 = 结果 | 照 NotebookLM：点格子直接展开会让人分不清「这是新做的还是以前的」 |
| 10-01 | 「全部录音」移出工作台，放进来源栏博主那一组的 ⋯ | 录音是来源不是产出 |
| 10-01 | 结果在工作台栏里展开，不盖住对话 | 看报告时常要接着问，对话不能被挡住 |
| 10-01 | 人名切换放在弹框里，不放在结果顶上 | 一份结果只属于一个人；在结果顶上换人等于偷偷换了这份结果 |
| 10-01 | 一个笔记本多个博主；合集 = 多个笔记本放一起 | 博主是共用的「人」，笔记本是研究问题 |
| 10-01 | 笔记本页顶栏只留图标 + 名字 + 同步 + ⋯ | 统计和运行详情一周看一次，不该常驻 |
| 10-03 | 界面上「项目」改叫「笔记本」（英文 Notebook）；对外宣传这个功能叫 Verbatim Notebook，产品仍叫 Verbatim | 照着 NotebookLM 做的，用过的人一看就懂；Verbatim（逐字）本身就是卖点，不改名，只给这个功能一个好记的全名 |
| 10-03 | 侧栏「笔记本」的图标从小人换成带线圈的本子 | 小人是「博主」时代留下的；改叫笔记本以后图标要跟名字对上，也要跟「资料库」那排书分得开 |
| 10-02 | 说话人从来源栏打开、在工作台栏展开，不做成工作台格子 | 说话人是来源的属性（录音里是谁），不是产出；跟「全部录音」同一处同一种容器 |
| 10-02 | 画面证据卡做成工作台格子，弹框里按期勾选（默认不勾） | 它是产出（从来源做一份新的），要花钱、要重下视频，所以先选范围看估价；做过的期在弹框里标「已做」、估价 0，别的笔记本里再选不重复花钱 |
| 10-02 | 音频播客做成工作台格子，结果是「播放器 + 逐句文字稿」，不单独做播放页 | 它是产出；文字稿每句带出处、原声行能跳回原视频那一秒，这是跟 NotebookLM 最大的区别，所以跟音频放在同一处、点句子就跳 |
| 10-02 | 代码库是来源（左栏、来源栏阅读器），「让 Daemon 读」在那一行的 ⋯ 里、点了先弹框看估价 | 代码是材料不是产出；读一次要几分钟、约 $0.3–2.5，加完不自动开读，先让人看到价钱和能填的问题 |
| 10-02 | 幻灯片的字不画进图里，模型只挑版式、填字段，排版是固定代码 | NotebookLM 被抱怨最多的就是整页是图、PPTX 改不了字；我们导出的是真文本框，引语和数字排版前在代码里对原文 |
| 10-03 | 幻灯片重做排版：每页都有圆底图标（Lucide 图标，模型从词表里挑），要点页轮换四种排法（编号卡片 / 图标行 + 本页要点 / 深色半幅面板 / 横条 + 引言） | 第一版每页都是「标题 + 三行小字 + 大片空白」，用户说太垃圾；对照 pptx skill 的参照稿，差距在视觉元素和版式变化 |
| 10-03 | 预览改成真 .pptx 渲染出的图（本机有 LibreOffice + pdftoppm 时），没有才退回 HTML 近似 | 两套画法会越走越不一样；看到的就该是下载到的 |
| 10-02 | 幻灯片预览里不放出处圆点，放在每页下面那一行 | 预览缩到窄屏时圆点比字还大、盖住内容；跟 .pptx 页脚列出处是同一个意思 |
| 10-02 | 幻灯片预览颜色用 --deck-* 并且不随暗色变 | 预览要跟导出的文件一模一样，文件本身不会变暗 |
| 10-02 | 「可能是同一个人」挂在说话人那一行里，带 ▶ 听对方 | 声纹在 0.6–0.75 之间的只能靠耳朵定；让用户在同一处听两个人、一键确认或否掉 |
