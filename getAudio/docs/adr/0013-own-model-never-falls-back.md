# 0013 用户自己的模型（OpenAI 兼容 / Ollama）：选了就不偷偷换云端

日期：2026-10-09

## 背景

照 Open Notebook 加「自己的模型」：Settings 里填一个 OpenAI 兼容端点（Ollama `http://localhost:11434/v1`、
LM Studio、OpenAI、自建网关）和模型名。Verbatim 别的模型都有兜底：国内模型（百炼 / DeepSeek / Kimi）报错这一次
改用 Gemini（`analyze._llm`），便宜路由失败回 Gemini（`llmroute`）。自己的模型要不要也这样？

选本机模型的人多半是为了内容不出本机（课堂录音、私人材料），或者为了不花钱。报错时悄悄把整段材料发给 Gemini，
两个目的都落空，而且用户看不出来。

## 决定

1. **分析大脑选「自己的模型」（预设 `custom`）时只用它**：报错就抛出、写明是哪个端点哪个模型，不改用任何云端模型。
   端点被清空了（老链条还记着 `custom`）才回落 Gemini 预设——那是配置没了，不是这一次失败。
2. **「日常文字也先用它」是另一个开关，默认关**：开了以后问答 / 摘要 / 标签 / 工作台先发给它，失败回 Gemini，
   跟便宜路由同一套（`llmroute._routes` 排第一，连着失败停用 30 分钟）。设置页上写明「它出错时改用 Gemini」。
   要严格不出本机的人别开这个开关，只在分析大脑里选它。
3. **记账**：端点是本机（localhost / 127.0.0.1 / ::1 / *.local）的记成服务商 `local`、$0；别的记成 `custom`，
   按价格表算，没价就是「没定价」（可在 prices.json 里补）。
4. 端点、模型名、开关每次调用时读 env，Settings 保存即生效；key 可空（Ollama 不要 key）。

## 后果

- 选了本机模型、本机模型没开（Ollama 没启动）时，分析会直接失败，要用户自己去开；这是故意的。
- 问答 / 工作台的流式回答也能走它（`llmroute.stream`）。思考模型吐出的 `<think>…</think>` 现在不处理（别的模型也没处理）。
- 测试：`tests/test_custom_llm.py`（本机起一个假的 OpenAI 兼容服务）；10-09 用本机 Ollama `qwen3-vl:8b` 实测过一次分析调用，9.6 秒、记 $0。
