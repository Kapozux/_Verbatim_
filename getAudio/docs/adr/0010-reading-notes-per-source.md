# 0010 每份来源一份读书笔记，工作台产出从笔记出发

日期：2026-10-03

## 背景

工作台（报告、闪卡、测验、播客、幻灯片）一次最多送 12 万 token 的原文。放不下时先是「每期拿第一段」（马督工 1021 期
拿到的全是片头），后来改成「看标题挑主题、按主题检索」。用户的意见：大量资料要像人一样先通读、再挑——
「丢给几十个 subagents 读完，然后你自己挑一挑，一些总结一些具体讲」，而且「要对每个 source 都适用（代码、图片、
文档、ppt/word……）」。

查过 NotebookLM 的做法：播客那边靠长上下文把来源大段读进去；聊天那边，来源一多「jam 不进 context window」，
靠检索。来源上限 50–600 个、每个 50 万词。

考虑过的做法：
- **整份塞进上下文（提高上限到 50 万 / 100 万 token）**：中等大小的笔记本够用，马督工 700 万 token 不够；
  长上下文「中间读不进去」；每期产出都把全部原文送两三遍，贵。
- **先定问题、再问自己的聊天、再写**：能扩到任意大小，但只找得到问到的东西，漏掉没想到要问的。
- **每期产出都并行分头读一遍（map-reduce）**：覆盖最全，但马督工每期播客都要花 $3–4、等几分钟。

## 决定

1. **每份来源读一次，存一份读书笔记**，按内容指纹存在来源旁边（文档 `results/_docs/<id>/notes.json`、转写
   `results/<tid>/notes.json`、代码库 `results/_repos/<id>/notes.json`），内容变了才重读；几个笔记本引用同一份来源共用。
2. **统一格式**：来源切成若干「块」，每块一份笔记——这一块讲什么、要点（每条带出处）、值得原样引用的话（带出处）、
   主题词。出处记来源内的段落下标（不带笔记本相关的编号），用的时候再换成 `d…-i` / `t…-i` / `r…-i`。
3. **按类型切块、按类型读**：
   - 文档（PDF / Word / Markdown / 网页 / 粘贴文字）：按段落顺序攒成块，尽量在页、小标题处断开；
     PDF 里几乎没字的页（图表、扫描）有 `pdftoppm` 时渲染成图一起给模型看。
   - PPT：块按幻灯片走；图多字少的幻灯片把幻灯片里的图片一起给模型看。
   - 图片：整张图给模型看（说明画了什么、抄出图上的字），不只靠 OCR。
   - 转写：按时间顺序攒成块；做过画面证据卡的期，画面卡也作为一块。
   - 代码库：Daemon 读过的按目录用它的卡；没读过的读快照里的文件（README 和源码优先、有上限），笔记的出处写「文件:行」。
4. **读用便宜模型、并行**：文字走 `ask._llm`（purpose `notes`，非中国议题可走便宜路由），带图的走多模态 flash-lite；
   一份来源的各块并行读。笔记用来源本身的语言写。
5. **什么时候读**：加来源后单份花费小的（约 $0.05 以下）后台自动读；一次很多的（频道、大代码库、整批）在左栏给估价，
   用户点了才读。读不了的（没字、太大、出错）记在笔记里、界面上标出来，不悄悄跳过。
6. **工作台放不下时从笔记出发**：第一步只看每份来源的块摘要，按「重点」（没写就用默认要求）定计划——几段、
   每段概括还是细讲、用哪些块；第二步看选中块的要点，挑出要用的出处；细讲的段落回到原文（出处段落和前后各一段）。
   计划和挑中的笔记一起写进提示词。笔记没读全的来源仍按原来的「挑主题检索」补上。材料一次放得下时照旧整份读。

## 后果

- 第一次读要花钱：文字每百万 token 约 $0.3–0.5，图片每张约 $0.001；马督工一次约 $3–4，IB 计算机科学约 $0.2。之后每期
  产出多两次便宜调用（几美分）。
- 每份来源多一个 `notes.json`（几 KB 到几十 KB）。
- 笔记是转述，可能漏或错；细讲时回原文、出处照旧逐条核对，就是为了不把转述当原文用。
- 聊天问答暂时不用笔记（检索已经够用）；以后「这些来源都讲了什么」这类概括问题可以接上。
