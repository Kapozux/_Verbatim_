# 0004 说话人按本机声纹认，跨录音一套固定叫法

日期：2026-10-02

## 背景

转写引擎（Qwen-ASR、Gemini 3.5、阿里云分离）给的「说话人1 / 说话人2」只在一份文件里有效：下一节课的说话人1
不一定是同一个人，长录音切块转写时同一份文件里也会重新编号。用户的语文课项目里，老师和学生几乎全被标成
说话人1，学生的插话、提问被算成老师说的。

考虑过的做法：
- **所有录音合并、单次转写**：几小时的音频超出引擎单次上限；一换文件就又要重来。
- **让大模型按上下文猜**：能分出「老师 / 学生」，分不出「哪个学生」，跨课更不行。
- **音频大模型判断两段是不是同一个人**：公开评测里接近瞎猜（Gemini 2.5 flash-lite 错 36%）。
- **专用声纹模型**：3D-Speaker CAM++ 中文版（20 万中文说话人训练，192 维）+ pyannote segmentation-3.0，
  经 sherpa-onnx 在本机 CPU 跑，Apache-2.0。课堂实测：老师在 8 节课里互相 0.96–0.99；同一个学生跨课 0.8–0.9；
  不同的人 0.2–0.5。

## 决定

1. **在本机算声纹，音频不上传。** 每条录音转完就切段、每段一个声纹，存进 `results/<tid>/voices.npz`，
   同时留一份 32 kbps 单声道试听音频 `voice.m4a`（每小时约 15 MB；换模型时也拿它重算——实测和原文件
   算出的声纹相似度 0.98）。模型不进仓库，放 `models/voices/`；没装模型时功能整个不出现。
2. **认人在项目里做**（`voices.identify`），结果和用户的决定存在项目目录的 `voices.json`：
   - 先在每条录音里把声音相近的段并成「组」（平均连接，门槛 0.6）；
   - 再跨录音把组并成说话人：**平均连接**（两边所有组合的相似度按时长加权平均），门槛默认 0.75。
     不用质心——质心会被「两边都有点像」的一组串起来，真实数据里把两个学生并成了一个；
   - 每次并最像的一对，跟处理顺序无关：给一个人改名、拆开，不会改变任何别人的归属（有测试）；
   - 一组里够长的话不到 10 秒的不单独编号，很像已有的人就并过去，否则归「未区分」——3 秒的门槛在真实
     课堂里冒出二三十个「学生」；
   - 0.6–0.75 之间只提示「可能是同一个人」，等用户听了确认。
3. **用户的决定是约束，也是校准数据。** 改名 / 设角色 / 合并把组「钉」在那个人身上；「这段不是 TA」记成不能并；
   两个都被用户认过的人永远不自动并。否掉过的最像的一对把门槛抬到它之上（最高 0.9）；确认过的不往下调——
   宁可多分几个人让用户合并，也不悄悄并错。
4. **证据卡存说话人 id（`v:p3`），名字现查。** 改名立刻生效，不用重新标卡。
5. **名字只认原话里点到的。** 没名字的说话人，把 TA 开口前别人说的话给便宜模型看；模型给的原话必须在转写里
   找得到、并且包含那个名字，才作为建议显示，从不自动改名。

## 后果

- 新转写的录音（项目里直接传、或之后加进项目）自动有声纹；以前的录音要找回原文件（按文件名在本机常用文件夹里找，
  时长对得上才用），找不到的让用户自己选文件。
- 只有「学生（未区分）」这一类是诚实的「不知道」：短于 1–2 秒的插话、同时说话的段，声纹本来就不可靠。
- 打包版要另外处理模型下载（37 MB）——还没做。
