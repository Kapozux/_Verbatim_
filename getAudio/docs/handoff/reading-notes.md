## 是什么
每份来源读一次存一份笔记（`notes.json`，放在来源自己的目录里，按内容指纹，内容变了才重读；几个笔记本共用）。
来源切成块，每块并行交给便宜模型（文字走 `ask._llm` purpose `notes`，带图走 `analyze._call_gemini_mm` + flash-lite），回来：
`{where, ids, summary, points: [{text, cite: [段落下标]}], quotes: [{text, cite}], topics}`。出处只留这一块里有的下标，引语必须原文里真有，不然丢掉。

| 来源 | 切块 | 读法 |
|---|---|---|
| PDF / Word / Markdown / 网页 / 粘贴文字 | 段落攒到 2.4 万字一块，在页 / 小标题处断 | 文字；PDF 里不到 80 字的页用 pdftoppm 渲染成图一起看 |
| PPTX | 同上（页 = 幻灯片） | 文字；字少的幻灯片里 8 KB 以上的图一起看 |
| 图片 | 一张一块 | 整张图给模型看 |
| 转写 | 按时间攒块 | 文字；做过画面证据卡的期，屏幕上的字单独一块 |
| 代码库 | Daemon 读过：按目录用卡；没读过：快照里的源码（README 优先，跳过 node_modules 等） | 出处是卡片下标 / 「文件:行」 |

## 什么时候读
- 加来源后 `_project_refresh` 最后调 `_notes_auto`：只看单独加的文档 / 代码库 / 录音，单份估价 ≤ $0.05 的自动读，一次最多 $0.25。
- 频道、引用博主的期：左栏「读剩下的 N 份（约 $x）」点了才读（`POST /api/chain/<id>/notes/read`）。
- 接口：`GET /api/chain/<id>/notes[?estimate=1&items=1]`、`GET /api/sources/notes?kind=&id=`。

## 工作台怎么用
`study._pick` 放不下全部原文时：勾选范围里至少一半来源读过笔记 → `_notes_plan`：把每份来源的块摘要（S3.2 [位置] 摘要 | 主题）给模型，
按「重点」（没写用默认要求）定 3–6 段，每段 overview / detail + 用哪些块；概括段只取要点引的段落，细讲段再补那几块的全部段落，预算按段平分；
博主频道没开原文检索的，转写段落由 `ask.note_cards` 现场补进 corpus。计划和挑中的笔记写进提示词（`corpus['_plan']` → `study._prompt`）。
笔记不够一半 → 退回「挑主题检索」。IB 计算机科学实测：19 份笔记 → 5 段计划，取 451 段原文（7.8 万 token），定计划这一步 $0.003、8 秒。
