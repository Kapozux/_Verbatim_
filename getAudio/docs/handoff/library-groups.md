# 资料库列表：按天分组、批量折叠、本地 / 网上筛选

## 速览

- **现状**：2026-11-18 在 worktree `.claude/worktrees/lib-groups`（分支 feature/lib-groups）做完；11-20 已合进本机 main、5001 在跑，GitHub 上走 PR #30。全套测试 84 个文件全过。
- **怎么跑**：资料库 → 转写记录。搜索框下面：全部 / 本地文件 / 网上的，再选博主 / 合集、转写时间（今天 / 近 7 天 / 某个月）、引擎。列表按天分组，一天里同一博主满 4 条折成一行，点开展开。
- **已知问题**：「本地文件」是按「没有原链接」认的，自己录的和从别处下好再传上来的 mp3 / mp4 分不开（真库 232 条里两种都有）；博主下拉 144 项是原生下拉，不能打字过滤；筛选状态不记，刷新就回到全部；约 350 条贴单条链接下的没有记博主名。
- **下一步**：用一阵看要不要给本地文件加一个「我录的」标记（手动标或按文件名 / 扩展名猜）；博主下拉换成能打字的；老的单条链接补博主名要联网查（没做，量大先问）。

## 做了什么

- 起因（用户 11-18）：「资料库搜索功能还是比较鸡肋：能不能按照不同的转写时间显示；太乱了，有我参与录制的、网上下载的（绝对大头，里面有列表、博主）」。真库 4597 条全平铺，单日最多一次灌进 680 条（一个频道），自己的录音被淹掉。
- 后端：`/api/history`、`/api/search` 每条多一个 `origin`（`app._origin`：有 `source_url` / `video_id` / 文件名里带 `[视频 id]` 的是 `web`，否则 `local`）。
- 前端（`static/app.js`「资料库列表」那一段）：`libF` 四层筛选 → `drawLibrary()` 算每层的条数、填下拉 → `buildLibRows()` 出「日期标题 / 折叠行 / 卡片」→ `drawMoreRows()` 一次画 120 行，滚到底（`IntersectionObserver`）再画。以前是一次画完 4000 多张卡片。
- 原来的「我的 / 来自博主库」和一排 10 个引擎标签拿掉了（`source` 字段接口里还在，别处在用）。
- 测试：`tests/test_history_fast.py` 加 4 条 `origin` 的；`tests/test_library.py` 比对时不看 `origin`。
- 验证：scratch 副本（`.claude/scratch-data/lib-groups`，只有 meta.json 和 chain.json）跑 5066，1700 / 1000 / 400 截图、展开折叠、切本地 / 网上、选博主，无报错、无横向滚动。不花钱。
